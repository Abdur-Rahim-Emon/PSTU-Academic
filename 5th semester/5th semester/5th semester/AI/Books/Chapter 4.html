Section 4.1

Local search algorithms

The foundation for every algorithm in this chapter

Purpose: Introduce a completely different style of search — one where you do NOT track the path. Only the current state matters.

In Chapter 3, search kept a full tree of every path explored. Local search throws that all away. It holds only one current state and moves to a neighbor of that state, again and again.

🏔 The blindfolded hiker analogy

Imagine you are blindfolded on a hilly landscape. You want to reach the highest peak. You can only feel if the ground under your feet goes up or down. You take a step in the best direction. You don't remember where you started or how you got here — only where you are right now.

This is local search. No memory of the path. Only the current state and what's nearby.

State-space landscape — the central metaphor

Think of every possible state as a point on a map. The "height" of each point equals how good that state is (the objective function value). Local search algorithms are explorers on this landscape trying to reach the highest peak.

Global maximum = best possible solution Local maximum = stuck point Shoulder = flat area with an exit Plateau = flat area, possibly no exit

Two goals of local search

1
Find a goal state — a complete, correct answer. Example: a valid solution to the 8-queens problem.
2
Optimization — find the best possible state according to an objective function. Example: maximize profit, minimize cost, find the best airport placement.

Section 4.1.1

Hill-climbing search

The most basic local search — always move to the best neighbor

Purpose: Show the simplest strategy and explain exactly why it often fails — motivating every other algorithm in the chapter.

Hill climbing (steepest-ascent version) is a loop that continuously moves in the direction of the highest-valued neighbor. It stops when no neighbor is better than the current state. It never looks further than the immediate neighbors — like trying to find the top of Mount Everest in a thick fog while suffering from amnesia.

📋 8-queens example

Each of 8 queens sits in one column. Any queen can move to another square in its column. Each state therefore has 8 × 7 = 56 successors. The heuristic cost h = number of attacking queen pairs. Goal: h = 0.

From a starting state with h = 17, the algorithm picks the neighbor with the best improvement (say h = 12). It reaches a near-solution (h = 1) in about 5 steps. But then it often gets stuck.

3 reasons hill climbing gets stuck

1
Local maximum — a peak that is higher than all its immediate neighbors but NOT the global maximum. Every move looks downhill, so the algorithm stops, even though far better states exist elsewhere in the space.
2
Ridge — a narrow upward slope in the landscape where all directly available moves point downhill. The algorithm cannot navigate sideways along the ridge and gets stuck at a false peak.
3
Plateau / shoulder — a flat area where all neighbors have the same value. A flat local maximum has no uphill exit at all. A shoulder does have an exit but you may not find it by always picking the best neighbor.

Variants (very common in exams)

Stochastic hill climbing — picks randomly among uphill moves (not always the steepest). Usually converges more slowly but can find better solutions in some landscapes.
First-choice hill climbing — generates random successors until one is better than the current state. Very efficient when a state has thousands of successors.
Random-restart hill climbing — "If at first you don't succeed, try, try again." Restarts from a random state whenever stuck. Trivially complete. For 8-queens: needs about 7 iterations on average to find a solution.
Sideways move — allow moving to a neighbor with equal value (not just higher). Limits must be set (e.g. max 100 sideways moves) to avoid infinite loops on flat maxima. Raises success rate from 14% → 94%.

Section 4.1.2

Simulated annealing

Escape local maxima by sometimes accepting worse moves

Purpose: Combine hill climbing (efficient) with a random walk (complete) to escape local maxima while still converging to a good solution.

The name comes from metallurgy. Annealing is the process of heating metal to a high temperature and then slowly cooling it. The atoms settle into a stable low-energy crystal structure. The algorithm copies this idea: start "hot" (accept many bad moves), then gradually "cool" (accept fewer bad moves).

🏓 Ping-pong ball analogy (from the textbook)

Imagine a bumpy surface and a ping-pong ball. If you just let it roll, it gets stuck in a shallow dip (local minimum). If you shake the surface hard at first and then gradually shake less and less, the ball bounces out of small dips but eventually settles in the deepest dip — the global minimum.

Simulated annealing = shaking the surface. Temperature = how hard you shake.

How the algorithm works — step by step

1
Pick a random neighboring state (not the best one — any random neighbor).
2
Calculate ΔE = new value − current value. If ΔE > 0 (move is better): always accept it.
3
If ΔE ≤ 0 (move is worse): accept it with probability e^(ΔE/T). When T is high (hot), this is close to 1. When T is low (cold), this is near 0.
4
Slowly reduce T according to a schedule. If T decreases slowly enough, the algorithm finds the global optimum with probability approaching 1.
Key difference from hill climbing: Hill climbing never accepts a worse move. Simulated annealing sometimes accepts worse moves, especially early on when T is high. This is exactly how it escapes local maxima.

Section 4.1.3

Local beam search

Track k states simultaneously — share information between threads

Purpose: Keep multiple "explorers" at once so promising regions get more attention. Unlike random restarts, these explorers communicate.

Basic hill climbing keeps 1 current state. Local beam search keeps k states at the same time. At each step it generates all successors of all k states, then selects the k best from that combined list and repeats.

🔑 Critical difference from k random restarts

In k random restarts, each search runs independently — they never share what they find. In local beam search, the k threads share information. If one thread finds a great region, resources shift toward it. The algorithm "abandons unfruitful searches and moves its resources to where the most progress is being made."

The diversity problem

In its basic form, the k states can all quickly cluster in the same small region of the state space, making it no better than an expensive version of hill climbing.

Fix: stochastic beam search — instead of always picking the best k successors, choose k successors at random, where better successors have a higher probability of being selected. This maintains diversity across the k states. It closely resembles natural selection in biology.

Section 4.1.4

Genetic algorithms

Combine two parents to create offspring — inspired by biological evolution

Purpose: Generate new states by combining two parent states (crossover) plus small random changes (mutation), mimicking how evolution produces new organisms.

A genetic algorithm (GA) is a type of stochastic beam search. The key difference: new states are made by combining two parents (crossover), not by modifying one state alone. This is sexual reproduction vs. asexual reproduction.

The 5 steps — memorize these

1
Initial population — start with k randomly generated states called individuals. Each state is encoded as a string. For 8-queens: an 8-digit string like 24748552 where each digit = row of the queen in that column.
2
Fitness function — score each individual. Higher = better. For 8-queens: number of non-attacking queen pairs. Maximum possible = 28 (all pairs non-attacking = solution).
3
Selection — choose pairs of parents to reproduce. Probability of selection is proportional to fitness score. Better individuals are chosen more often.
4
Crossover — pick a random position in the string (crossover point). Child inherits the first part from Parent A and the second part from Parent B. This combines useful "blocks" from both parents.
5
Mutation — with a small random probability, change one character in the child string. Prevents the population from becoming too uniform and losing diversity.
✂️ Crossover example from the textbook

Parent A: 32752411  |  Parent B: 24748552

Crossover point after position 3 → Child: 32748552

The child inherits the first 3 digits from A and the last 5 from B.

Schema — the theory behind why GAs work

A schema is a pattern in the string where some positions are left unspecified using *. Example: 246***** matches all 8-queens states where the first three queens are in rows 2, 4, 6. Strings matching the schema are called instances.

If instances of a schema have above-average fitness, the GA naturally produces more of them over generations. This is why GAs work — they find and combine good building blocks.

Real-world uses: circuit layout (VLSI), job-shop scheduling. GAs work best when the string representation maps to meaningful real-world components — so the "good blocks" actually correspond to useful sub-solutions.

Section 4.2

Local search in continuous spaces

What changes when the state space has infinite possible points

Purpose: Most algorithms above assume a discrete state space. The real world is continuous. This section shows how to handle infinite state spaces.

In a discrete problem, you pick from a finite list of neighbors. In a continuous problem, there are infinitely many neighbors in every direction (infinite branching factor). You cannot list them all, so you need different techniques.

🗺 Airport placement example (from textbook)

Place 3 airports in Romania to minimize the total squared distance from every city to its nearest airport. The state space has 6 variables: (x1,y1), (x2,y2), (x3,y3). Moving in this space = physically moving an airport on the map. Every real number is a valid coordinate — infinite choices.

Two approaches to handle continuous spaces

1
Discretization — artificially divide the space into steps of ±δ. Move each variable by a small fixed amount. With 6 variables this gives 12 possible moves. Then apply any standard local search algorithm.
2
Gradient methods — use calculus. The gradient ∇f is a vector that gives the direction and steepness of the steepest uphill slope at the current point. Move in that direction by a step size α.

Update rule: x_new = x + α · ∇f(x)

This is called gradient ascent (maximizing) or gradient descent (minimizing).
Solving ∇f = 0 analytically finds the exact optimum — but only works for simple problems. For complex problems (like 3 airports), the gradient depends on which cities are closest to which airport, so it changes as you move. You must compute it locally and step iteratively.
