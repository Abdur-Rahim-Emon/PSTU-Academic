15-1 TCP Services

What does TCP promise to deliver?
Purpose: TCP sits between the Application Layer and Network Layer. It acts as a middleman that provides reliable, ordered, full-duplex communication between two processes (not machines — processes!).
📬 Analogy: UDP is like dropping a letter in a mailbox — you don't know if it arrives. TCP is like sending a registered parcel with tracking, signature confirmation, and re-delivery if it fails.
① Process-to-Process Communication

TCP identifies communication endpoints using port numbers, not IP addresses. IP addresses identify machines; ports identify the specific application/process on that machine.

Client App
(Port 52000)
⟷ TCP ⟷
Web Server
(Port 80)
Exam tip TCP uses port numbers for process-to-process communication; IP uses IP addresses for host-to-host.
② Stream Delivery Service

TCP treats data as a continuous stream of bytes, not individual packets. The sending application writes bytes into a sending buffer; TCP groups these into segments to send; the receiving buffer holds them until the receiving application reads them.

Key The boundary between messages is NOT preserved by TCP — it's a stream, not a message service.
③ Full-Duplex Communication

Data can flow in both directions simultaneously. Each side has its own send and receive buffer. This is why TCP uses piggybacking — data and acknowledgments travel together in the same segment.

④ Multiplexing and Demultiplexing

Multiplexing: Many processes on the sender can share TCP (combine into one stream). Demultiplexing: TCP at the receiver separates incoming data and delivers it to the correct process using port numbers.

⑤ Connection-Oriented Service

Before data transfer, TCP must establish a logical connection (virtual circuit). After transfer, it terminates the connection. This is done via the 3-way handshake (explained in Section 15-4).

⑥ Reliable Service

TCP uses acknowledgment numbers and timers to ensure every byte of data is received. If a segment is lost or corrupted, TCP retransmits it automatically.

15-2 TCP Features

How TCP implements those services
Purpose: These are the internal mechanisms TCP uses. Think of them as tools in TCP's toolbox to keep its promises.
🔢 Numbering System

TCP assigns a sequence number to every byte of data, not to each segment. The sequence number in a segment header = the number of the first byte in that segment.

Key Rule Numbering starts at an arbitrarily generated random number (not 0 or 1) — this is for security.
── Example 15.1 ────────────────────────────────── File size : 5,000 bytes First byte # : 10,001 Segment size : 1,000 bytes each Total segments: 5 Segment 1: bytes 10,001 – 11,000 → seq# = 10,001 Segment 2: bytes 11,001 – 12,000 → seq# = 11,001 Segment 3: bytes 12,001 – 13,000 → seq# = 12,001 Segment 4: bytes 13,001 – 14,000 → seq# = 13,001 Segment 5: bytes 14,001 – 15,000 → seq# = 14,001
Exam tip The sequence number = number of the first data byte in the segment. The acknowledgment number = number of the next byte the receiver expects. ACK is cumulative.
ISN
Initial Sequence Number — randomly generated at connection start
ACK
Acknowledgment = next byte expected (cumulative)
Seq#
Number of first byte in that segment
🌊 Flow Control

Controls how much data the sender can send before getting an ACK. The receiver advertises a receive window (rwnd) — how many bytes of buffer space it has available. The sender must not exceed this.

Key Flow control protects the receiver from being overwhelmed. Congestion control protects the network.
🛡️ Error Control

Ensures reliable delivery using: checksum (detect corruption), acknowledgment numbers (confirm receipt), and timers/retransmission (recover lost segments).

🚦 Congestion Control

TCP monitors network traffic and reduces its sending rate when congestion is detected. Uses a congestion window (cwnd) in addition to rwnd.

15-3 TCP Segment Format

The structure of every TCP packet
Purpose: A TCP packet is called a segment. Each segment has a header (minimum 20 bytes, max 60 bytes) and a data portion. The header fields tell TCP what to do with the data.
📦 Analogy: A segment is like a shipping box. The header is the label on the box (who it's for, tracking number, handling instructions). The data is what's inside.

Exam tip The 6 flags in order: URG · ACK · PSH · RST · SYN · FIN
📐 HLEN Field

HLEN (Header Length) is 4 bits. Its value × 4 = header size in bytes.

  • Minimum value = 5 → 5 × 4 = 20 bytes (minimum header)
  • Maximum value = 15 → 15 × 4 = 60 bytes (maximum header)
Exam tip Min header = 20 bytes | Max header = 60 bytes | Options can add up to 40 bytes
🔒 Pseudoheader & Checksum

For checksum calculation, TCP uses a pseudoheader — a temporary 12-byte structure that includes the source IP, destination IP, protocol number, and TCP length. This is added before computing the checksum, then discarded.

Critical Checksum in TCP is mandatory. (In UDP it is optional.)

15-4 A TCP Connection

Establishment · Data Transfer · Termination
Purpose: TCP must establish a virtual connection before sending data, even though the underlying IP layer is connectionless. The connection is managed by TCP itself — if a segment is lost, TCP retransmits it.
🤝 Connection Establishment — 3-Way Handshake
📞 Analogy: Like a phone call. You dial (SYN) → they answer "Hello?" (SYN+ACK) → you say "Yes, hello!" (ACK) → conversation begins.

Key facts SYN segment cannot carry data but consumes 1 sequence number. SYN+ACK cannot carry data but consumes 1 sequence number. ACK with no data consumes NO sequence number.
Exam tip "3-way" because there are 3 steps: SYN → SYN+ACK → ACK
📤 Data Transfer

After connection establishment, both sides can send data. TCP uses piggybacking — acknowledgments are sent inside data segments going the other direction, saving bandwidth.

  • Each data segment is acknowledged by the receiver
  • The ACK number = next byte expected (cumulative)
  • Timers start when a segment is sent; if no ACK within timeout → retransmit

CLIENT (Active Close) SERVER (Passive Close)

Key facts FIN segment consumes 1 seq# if it carries no data. FIN+ACK also consumes 1 seq# if no data.
½ Half-Close

One side can close its sending direction while still receiving data from the other side. The side that sends FIN can still receive data until the other side also sends FIN. This is called a half-close.

📞 Analogy: You say "I have nothing more to say" but you still listen until the other person finishes talking.
⚡ Connection Reset

A RST flag aborts a connection immediately — no graceful close. Used when an error occurs or an unexpected segment arrives. The connection is discarded with no cleanup.

15-6 Windows in TCP

Send Window & Receive Window
Purpose: TCP uses a sliding window mechanism to allow multiple segments to be in transit simultaneously without waiting for each individual ACK. This improves efficiency.
🪟 Analogy: Imagine sending 10 letters, but you can only have 3 in the postal system at once. Once one gets delivered (ACK), the window slides forward, and you can send the next one.
📤 Send Window

The send window has three regions based on sequence numbers:

RegionDescription
Already sent & acknowledgedPurged — no longer needed
Sent but not yet acknowledgedOutstanding — waiting for ACK
Can be sent (within window)Ready to send — buffer is available at receiver
Cannot send yetBeyond window — receiver buffer may be full
Exam tip Window size is controlled by the receiver's advertised window (rwnd) value in ACK segments.
📥 Receive Window

The receiver has a buffer. It advertises how many bytes it can currently accept. The sender must respect this limit. The receiver updates rwnd in each ACK.

  • If rwnd = 0 → sender must stop sending (zero-window condition)
  • Receiver can increase rwnd as it processes data from its buffer
Warning Window shrinking can cause problems — the receiver should avoid advertising a smaller window than before if possible (see Example 15.2 in slides).
rwnd
Receive window — buffer space at receiver
cwnd
Congestion window — network capacity limit
min(rwnd, cwnd)
Actual send window = smaller of both

15-7 Flow Control

Matching sender speed to receiver capacity
Purpose: Flow control prevents a fast sender from sending more data than a slow receiver can handle. It is end-to-end control (between sender and receiver), NOT network-level control.
🍽️ Analogy: A waiter (sender) filling a plate (receiver buffer). If the plate is getting full, the diner says "slow down." The waiter only pours as fast as the diner can eat.
📏 Opening and Closing Windows

The receiver controls the send window by changing the rwnd value in ACK segments:

  • Opening the window: receiver increases rwnd as it consumes data → sender can send more
  • Closing the window: receiver decreases rwnd as its buffer fills → sender must slow down
  • Zero window: rwnd = 0 → sender must stop. Sender sends periodic "probe" segments to check if window reopens
Exam tip The receiver controls flow by adjusting rwnd. It does NOT control the sender directly — it only tells the sender how much buffer space is available.
⚠️ Shrinking of Windows

Window shrinking happens when: LastACK + new_rwnd < LastACK + old_rwnd

This can cause a problem: bytes already sent may fall outside the new window boundary. The recommended solution: the receiver should delay sending feedback until enough buffer space is available.

Rule The right edge of the window should not move backward. Avoid shrinking windows.

15-8 Error Control

Detecting and correcting lost/corrupted segments
Purpose: TCP guarantees that all data arrives correctly and in order. Error control uses three tools: checksum, acknowledgment, and timers.
🔧 Three Tools of Error Control
ToolPurposeHow it works
ChecksumDetects corruptionReceiver checks; if bad → discards segment silently
ACK NumberConfirms receiptTells sender next expected byte; cumulative
Timer / TimeoutDetects lost segmentsIf no ACK before timeout → retransmit segment
Key TCP receiver delivers only ordered data to the application. Out-of-order segments are held in buffer until gaps are filled.
📋 6 Rules for Generating ACKs
1
Piggybacking: When A sends data to B, it includes an ACK for what B sent. Reduces total segment count.
2
Delayed ACK: If only 1 in-order segment is outstanding (previous already ACKed), delay the ACK up to 500 ms waiting for another segment or data to piggyback on. Reduces ACK traffic.
3
Two in-order, unACKed: If a second in-order segment arrives and the first isn't acknowledged yet → send ACK immediately. At most 2 in-order unACKed segments allowed.
4
Out-of-order (gap detected): If a segment arrives with seq# higher than expected (a gap exists) → send duplicate ACK immediately for the last in-order segment received. This triggers fast retransmission.
5
Missing segment arrives: When the missing segment finally arrives → send ACK for the next expected byte to confirm gap is filled.
6
Duplicate segment: If the same segment arrives twice → discard it, but immediately send ACK for next expected byte. Solves cases where the ACK itself was lost.
Exam tip Delayed ACK waits max 500 ms. Fast retransmission is triggered by 3 duplicate ACKs (you receive the original ACK + 3 more for same seq# = 4 total).
⚡ Fast Retransmission

If the sender receives 3 duplicate ACKs (all requesting the same sequence number), it retransmits the missing segment immediately, without waiting for the timeout. This is much faster than waiting for a timer.

❌ Lost Acknowledgment Problem

If an ACK is lost, the sender will retransmit the segment. The receiver gets a duplicate segment but handles it using Rule 6: discard and send ACK again.

Critical Note Lost acknowledgments may create deadlock if not properly handled (e.g., zero-window probe segments solve this).

15-9 Congestion Control

Preventing network overload
Purpose: Unlike flow control (which protects the receiver), congestion control protects the network. When too many senders send too much data, routers drop packets. TCP detects this and reduces its sending rate.
🔄 Open-Loop vs Closed-Loop
TypeMeaning
Open-LoopPrevent congestion before it happens (proactive)
Closed-LoopDetect and respond to congestion after it starts (reactive)
Key TCP uses both open-loop and closed-loop congestion control mechanisms.
📈 Congestion Window (cwnd)

TCP maintains a congestion window (cwnd). The actual window a sender uses = min(rwnd, cwnd).

  • Slow Start: Begin with cwnd = 1 MSS; double cwnd every RTT (exponential growth)
  • Congestion Avoidance: When cwnd reaches ssthresh, increase by 1 MSS per RTT (linear growth)
  • Congestion Detection: If timeout → cwnd = 1, ssthresh = half of cwnd. If 3 dup ACKs → ssthresh = half, cwnd = ssthresh (fast recovery)
Exam tip Slow Start is exponential growth. Congestion Avoidance is linear (additive) growth. This is called AIMD (Additive Increase Multiplicative Decrease).

15-11 TCP Options

Optional header extensions
Purpose: TCP header can have up to 40 bytes of optional information. Options extend TCP's capabilities beyond the basic header.
📋 Two Categories of Options
CategoryTypes
1-byte optionsEnd of Option List, No Operation (padding)
Multiple-byte optionsMaximum Segment Size (MSS), Window Scale Factor, Timestamp, SACK-Permitted, SACK
📏 MSS — Maximum Segment Size

Specifies the largest segment TCP will accept. Negotiated during 3-way handshake (in SYN segments). Default = 536 bytes if not specified.

🪟 Window Scale Factor

Extends window size beyond 65,535 bytes (the 16-bit limit). Shifts the window value left by a scale factor (multiplier). Important for high-speed networks.

⏱️ Timestamp

Used to measure RTT (Round-Trip Time) accurately and to handle sequence number wraparound on very fast links (PAWS — Protection Against Wrapped Sequence numbers).

✅ SACK & SACK-Permitted

SACK = Selective Acknowledgment. Allows receiver to tell sender exactly which bytes were received, so only the truly missing segments are retransmitted (more efficient than retransmitting everything after the loss).

Exam tip 5 types of multiple-byte options: MSS · Window Scale · Timestamp · SACK-Permitted · SACK
