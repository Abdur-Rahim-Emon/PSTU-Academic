What is a Routing Protocol?
Purpose: Decide the best path for data to travel across the internet
Simple Description

Imagine you want to send a letter from Dhaka to London. There are many roads and flights. Someone must decide: which path is fastest? Which is cheapest? In networking, routing protocols do exactly this — they find the best path for data packets to travel from one computer (source) to another (destination) across many routers.

  • Path = the sequence of routers a packet travels through from source to destination.
  • "Good" path means: least cost, fastest, or least congested (not stuck in traffic).
  • Routing is considered a "top-10" networking challenge because it is very complex.
MCQ / Fill-in-the-blank Ready
  • A routing protocol determines _____ paths from sending hosts to receiving hosts. (Answer: "good" / least-cost)
  • A path is the sequence of _____ a packet passes through. (Answer: routers)
  • "Good" path can mean: least _____, fastest, or least _____. (Answer: cost; congested)

Graph Abstraction & Link Costs
Purpose: Represent the network as a math graph so we can calculate shortest paths
Simple Description

We model the internet as a graph. Think of it like a map where cities are routers and roads between them have distances (costs).

  • G = (N, E) where:
    • N = set of nodes (routers): e.g. { u, v, w, x, y, z }
    • E = set of edges (links/roads between routers)
  • c(a, b) = cost of the link between router a and router b
  • If two routers are not directly connected, the cost = ∞ (infinity)
  • Cost can mean: bandwidth, delay, congestion, or always just "1"
Example from slide

In the graph with routers u, v, w, x, y, z:

  • c(w, z) = 5  → they are connected with cost 5
  • c(u, z) = ∞  → u and z have no direct link
  • c(u, x) = 1  → cheapest direct link

  • c(a,b) = ∞ means routers a and b are _____ directly connected. (not)
  • Link cost can be inversely related to _____. (bandwidth or congestion)

Dijkstra's Link-State Algorithm — The Concept
Purpose: Find the shortest (least-cost) path from ONE router to ALL other routers
Simple Description

Dijkstra's algorithm is like a person standing at a starting city, wanting to find the cheapest route to every other city on the map. It keeps checking routes step by step, always picking the cheapest unexplored option first.

Key properties:

  • Centralized: Needs the full network map (link costs) to be known to all nodes — done via "link state broadcast."
  • Iterative: After k steps, we know the shortest path to k destinations.
  • Result: Produces a forwarding table — "to reach destination X, send packet out on link Y."
Key Notation (Very Important for Exams!)
SymbolMeaning
c(x, y)Direct link cost between x and y. = ∞ if not neighbors.
D(v)Current best estimate of cost from source to node v
p(v)Predecessor of v — the node just before v on the best path
N'Set of nodes whose final shortest path is confirmed/known
The Algorithm Logic (Plain English)
1
Initialization: Start at source node u. N' = {u}. For each neighbor of u, set D(neighbor) = direct link cost. For all others, D = ∞.
2
Loop: Find the node w not yet in N' that has the smallest D(w). Add w to N' (its path is now final!).
3
Update neighbors: For every neighbor v of w (not in N'), check if going through w is cheaper:
D(v) = min( D(v), D(w) + c(w, v) )
4
Repeat until all nodes are in N'.

  • p(v) is the _____ node along the path to v. (predecessor)
  • Dijkstra's is a _____ algorithm (needs full topology). (centralized)

Dijkstra's Algorithm — Step-by-Step Example
Purpose: See exactly how the algorithm works on a real network graph
The Network (from Slide 10)

Nodes: u, v, w, x, y, z. Source = u. Direct link costs from u:

  • u→v = 2, u→x = 1, u→w = 5 (via the graph)
  • u→y = ∞ (not direct), u→z = ∞ (not direct)

Other links: v-x=2, v-w=3, x-w=3, x-y=1, w-y=1, w-z=5, y-z=2

Step-by-Step Walkthrough

Step 0 — Initialization:

  • N' = {u}
  • D(v) = 2 (direct), p(v) = u
  • D(x) = 1 (direct), p(x) = u
  • D(w) = 5 (direct), p(w) = u
  • D(y) = ∞ (not direct)
  • D(z) = ∞ (not direct)

Step 1 — Pick smallest D not in N':

Smallest is D(x) = 1 → add x to N'. Now N' = {u, x}

Update x's neighbors not in N':

  • D(v) = min(2, D(x)+c(x,v)) = min(2, 1+2) = 2, p(v)=u (no change)
  • D(w) = min(5, D(x)+c(x,w)) = min(5, 1+3) = 4, p(w)=x ✅ updated!
  • D(y) = min(∞, D(x)+c(x,y)) = min(∞, 1+1) = 2, p(y)=x ✅ updated!

Step 2 — Pick smallest D not in N':

Tie: D(v)=2 and D(y)=2. Pick y (or v — either works). Add y. N' = {u, x, y}

Update y's neighbors:

  • D(w) = min(4, D(y)+c(y,w)) = min(4, 2+1) = 3, p(w)=y ✅
  • D(z) = min(∞, D(y)+c(y,z)) = min(∞, 2+2) = 4, p(z)=y ✅

Step 3 — Pick smallest D not in N':

D(v)=2 is smallest. Add v. N' = {u, x, y, v}

Update v's neighbors:

  • D(w) = min(3, D(v)+c(v,w)) = min(3, 2+3) = 3 (no change)

Step 4 — Pick smallest D not in N':

D(w)=3 is smallest. Add w. N' = {u, x, y, v, w}

Update w's neighbors:

  • D(z) = min(4, D(w)+c(w,z)) = min(4, 3+5) = 4 (no change)

Step 5 — Last node:

Only z remains. D(z)=4, p(z)=y. Add z. N' = {u, x, y, v, w, z}. Done!

Final Shortest Paths from u
DestinationCostPath
v2u → v
x1u → x
y2u → x → y
w3u → x → y → w
z4u → x → y → z

Resulting Forwarding Table
Purpose: Use the shortest paths to build the router's forwarding table
Simple Description

After Dijkstra's finishes, the router u uses the results to build its forwarding table. This table tells u: "If a packet is going to destination X, which outgoing link should I send it on?"

The key insight: even if the final destination is far away, the packet just needs to know the first hop (next link).

Forwarding Table at Router u
DestinationOutgoing Link (First Hop)Reason
v(u, v)Direct path to v
x(u, x)Direct path to x
y(u, x)Path: u→x→y, so go via x
w(u, x)Path: u→x→y→w, so go via x
z(u, x)Path: u→x→y→z, so go via x

Notice: almost all destinations go through link (u,x) first — because x is the cheapest first step!

MCQ / Fill-in-the-blank Ready
  • A forwarding table maps each _____ to an outgoing _____. (destination; link)
  • In the example, to reach z from u, the outgoing link is _____. (u,x)
  • The result of Dijkstra's algorithm gives the _____ table for a router. (forwarding)

Dijkstra's Algorithm: Complexity
Purpose: Understand how efficient (or slow) Dijkstra's algorithm is
Simple Description

When we say complexity, we ask: "As the number of routers (n) grows, how much more work does the algorithm need?"

Algorithm Complexity (how many comparisons):

  • In each of the n iterations, we check all nodes not yet in N' → up to n comparisons per step
  • Total comparisons: n + (n-1) + … + 1 = n(n+1)/2
  • This is O(n²) — meaning if the network doubles in size, computation quadruples
  • More efficient versions exist using priority queues: O(n log n)

Message Complexity (how many messages routers send):

  • Each router must broadcast its link-state info to all other n routers
  • Each broadcast message crosses O(n) links
  • Total message complexity: O(n²)
MCQ / Fill-in-the-blank Ready
  • The basic complexity of Dijkstra's algorithm with n nodes is _____. (O(n²))
  • More efficient implementations of Dijkstra's can achieve _____ complexity. (O(n log n))
  • The number of comparisons in Dijkstra's basic version is _____. (n(n+1)/2)
  • In link-state routing, each router must _____ its link state to other routers. (broadcast)

Oscillations in Dijkstra's Algorithm
Purpose: Understand a serious problem that can happen when link costs depend on traffic
Simple Description

Normally, link costs are fixed. But what if link costs change depending on how much traffic is on them? Then a strange problem called oscillation can happen: routes keep changing back and forth, never settling!

Real-World Analogy

Imagine a highway that is cheap when empty and expensive when crowded. Everyone takes it, so it gets crowded → everyone switches to another road → that road gets crowded → everyone switches back… and so on forever. This is oscillation.

Why it happens in networks:

  • All routers run Dijkstra's at the same time with the same cost info
  • They all pick the same "best" low-cost path → that path becomes congested
  • Next round: costs are recalculated, all switch to a different path
  • The cycle repeats → routes oscillate (keep changing)

Solution: Routers can randomize when they run the algorithm (not all at the same time) to avoid synchronized switching.

MCQ / Fill-in-the-blank Ready
  • Route oscillations occur when link costs depend on _____ volume. (traffic)
  • Oscillations happen because all routers compute new routes _____ using the same information. (simultaneously / at the same time)
  • True/False: Oscillations are possible when link costs are always fixed at 1. (False)
  • One solution to prevent oscillations is to _____ the time routers compute routes. (randomize / offset)
